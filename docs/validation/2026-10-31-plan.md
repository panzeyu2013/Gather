## 1. 证明什么，怎么判

### 1.1 五个问题 → 八道门

| 要证明的事 | 门 | 一句话判据 |
|---|---|---|
| 数据不丢 | V1 | 任一步失败，原片字节不变；清空后 C1/Bridge 都读不到；归档/恢复/集合/堆栈不丢行 |
| AI 可信 | V4 | 闭眼/合焦/审美/语义/时延达到阈值，否则不宣称“自动初审” |
| C1/Bridge 互操作 | V2 | C1 看到星级/关键词/色标；Bridge 看到 caption/版权；不产生重复边车 |
| 100k 可用 | V5 | 相对基线不劣化 >20%；facet p95 <1s；语义 20k <1.5s；内存 <2GB |
| 可发布 | V7/V8 | 干净安装、旧库归档、Keychain、日志脱敏、签名/公证、回归全绿且测试能判红 |

V0 是前置：基线不可信，后面七道门的结论都不成立。

### 1.2 缺陷分级

- **P0（阻断发布）**：数据丢失/损坏；写回不生效；C1/Bridge 读不到；崩溃后原片或库不可恢复；安装/启动失败；签名/公证失败；100k 下不可用（p95 超预算 2× 或 OOM）。
- **P1（可降级承诺）**：指标未达标但有明确降级文案；单点 UI 阻断有绕行；性能超预算 ≤2×。
- **P2**：文案、外观、余量。

### 1.3 判定规则

1. 任一 P0 = no-go；P1 必须进 known issues 并写解除条件。
2. 失败必须复现 3 次并保留原始日志；**flaky 按失败处理**，不允许“重跑绿”结案。
3. 每道门单独出 go/no-go，不因其它门绿而豁免。
4. 只信独立回读：App 自报“已写入”不算，必须用 ImageIO/Bridge/C1/字节 diff 复核。

### V1 数据安全 🟡

**目的**：证明写回/清空/崩溃/外部修改/备份恢复/保留期都不会丢数据。

#### 样本

| 组 | 数量 | 内容 |
|---|---|---|
| A 全内嵌 | 30 | EXIF + XMP + IPTC-IIM + ICC + APP2，含 rating/label/keywords/caption/copyright |
| B Bridge 形态 | 20 | 仅 IPTC-IIM（caption/copyright/keywords），无 XMP |
| C XMP-only | 20 | 仅 APP1 XMP（C1 常见形态），无 IIM |
| D 非 ASCII | 10 | 中文/日文文件名与 caption、关键词 |
| E 大 IPTC（负向） | 10 | 非标准大 IIM 拆分：ImageIO 只读其中一段、App 读首段；只验证“显式/可解释、不静默丢”，**不作互操作基线** |
| F 无元数据 | 10 | 相机直出，无 APP1/APP13 |
| RAW+JPEG | 20 组 | C1 会话导出：.CR3/.RAF/.ARW + .JPG + .XMP（**待提供**） |

夹具由 `scripts/validation/fixtures.py` 生成（Pillow 12；系统 sRGB ICC），`verify` 校验段结构/SHA/XMP XML；独立回读用 `scripts/validation/inspect_jpeg.swift`（ImageIO）。100 张矩阵已生成并通过（A30/B20/C20/D10/E10/F10，3.9 MB，清单带 SHA256）。

#### 步骤

1. **基线哈希**：`shasum -a 256` 全量；同时算每张图 SOS→EOF 的 scan SHA（单独脚本，排除头部）。
2. **导入**：GUI 导入 100 张到独立数据目录；等 `metadata.scan` 完成；记录 `sessions.photo_count` 与 `assets` 行数。
3. **写回**：改 rating/label/keywords/caption/copyright，触发写回；等 delivery 终态。
4. **写后校验**：
   - scan SHA 与步骤 1 完全相同；
   - 非 XMP/APP13 段逐字节相同（段 diff）；
   - XMP 与 IIM 双读一致（App 面板 + 独立 ImageIO 读回）。
5. **清空**：清空 caption/copyright/keywords；确认 XMP 与 IIM 都消失，Bridge/C1 读不到；重开 App 不复活。
6. **崩溃注入**（6 点，见附录 C）：`kill -9` 或 hook 注入；重启后原片字节不变；无孤儿 `.gather-embedded-*`、`.gather-header-*` 可解释残留。
7. **外部并发修改**：写回前用另一进程改 mtime/内容/替换文件；预期 `conflict/externalConflict`，原片不被覆盖。
8. **备份/恢复**：设置 `backup_dir`；备份 → 删除/损坏库 → 恢复；行数与集合/堆栈/校样不丢。
9. **保留期清理**：设置 `backup_retention`；跑维护；确认过期备份被删且 DB 引用同步清理，不误删当前库。
10. **DB 对账**：附录 B 查询逐项与 UI 计数一致。

#### 通过标准

- 任一步失败，原片字节不变（SHA 全等）。
- 写后 scan SHA 不变；XMP+IIM 双读一致；清空后两种读取都不再返回旧值。
- 无孤儿临时文件；崩溃恢复后 delivery 可重试并收敛。
- 归档/恢复/集合/堆栈/校样行数不丢，外键 `foreign_key_violations=0`。
- 大 IIM 拆分样本（E）允许失败，但必须显式报错或可解释地只读首段；不得静默丢字段。

**证据**：`SHA256SUMS`、scan SHA 表、段 diff、DB 查询 TSV、崩溃点日志、恢复前后 `sqlite3 .dump` 行数。

**当前阻塞**：RAW+JPEG 20 组需用户提供；A–F 可由夹具生成。

### V2 C1 / Bridge 互操作 🟡

**目的**：证明写回在 C1 与 Bridge 里“看得见、改得回、不重复”。

#### 版本矩阵（D1 冻结）

| 软件 | 本机 | 验收 |

| Bridge | 14.0 | 本机 |
| LrC | 未安装 | 未验证（不阻塞） |

#### C1 分支

1. 写回 rating/keywords/label 到 3 张（XMP-only、全内嵌、RAW+JPEG 各一）。
2. 观察 C1 自动 reload（`c1_auto_reload=1`，debounce 1.5s）：星级/关键词/色标可见。
3. 裁剪叠层：sidecar 写 `crs:Crop*`，C1 显示裁剪；Gather 只读提示，不改写。
4. 未安装 C1 时 0 次 `/usr/bin/osascript`：**需无 C1 机器/VM**；本机只能跑 `C1Installation` 单测，不能替代实机。
5. 记录 C1 版本、截图、reload 耗时、失败时的 TCC/Apple Event 错误。

#### Bridge 分支

1. Bridge 打开 JPEG，确认 caption/版权/关键词来自内嵌 IPTC。
2. 在 Bridge 改 caption/版权 → Gather 重新读元数据 → 面板同步。
3. 反向：Gather 写 → Bridge 重新加载可见。
4. 检查不产生重复边车：同目录只允许一个同名 `.xmp`（大小写敏感卷见下）。

#### 卷/大小写

```bash
hdiutil create -size 200m -fs "Case-sensitive APFS" -volname GatherCase /tmp/GatherCase.dmg
hdiutil attach /tmp/GatherCase.dmg
# 复制 IMG_0001.JPG + IMG_0001.XMP / img_0001.xmp，验证不产生双份、不覆盖错文件
hdiutil detach /Volumes/GatherCase
```

exFAT 同法（`-fs ExFAT`）。网络卷（SMB）需外部服务，记未验证或另约。

#### 通过标准

- C1 能看到星级/关键词/色标；Bridge 能看到 caption/版权；双向修改可回读。
- 无重复边车；大小写卷不产生双份。
- 无 C1 时不 spawn osascript、不弹 TCC。

**证据**：C1/Bridge 截图（含版本号）、XMP 回读文本、`log show` 的 osascript 计数、卷上文件清单。

**当前阻塞**：无 C1 机器、LrC、SMB 服务。

### V3 端到端工作流 ⛔

**目的**：证明真实规模下全流程可完成、计数一致、失败可重试。

#### 三个会话

| 会话 | 规模 | 数据 |
|---|---|---|
| 婚礼 | 2k RAW+JPEG | 需用户提供 |
| 活动 | 5k JPEG | 需用户提供 |
| JPEG-only | 1k | 可用合成/公开图先做演练 |

#### 步骤（每个会话一遍）

1. 导入 → EXIF 重命名 → 第二目的地；核对文件数与命名冲突。
2. 质量评分 + 模型初审 → triage（keep/reject/review）→ 人工抽检。
3. 挑片：keep/reject、星级、色标、对比、撤销/重做。
4. 淘汰移出 → `_rejects`；RAW/JPEG 同移；共享 `.xmp` 复制；确认不删除。
5. 关键词/集合/堆栈；确认 facet 计数与网格一致。
6. 配方 → 联系表 → 画廊 → 校样；导出目录清单与 manifest。
7. 导入 `selection.json`（v1 勾选 / v2 反馈）：pick/rating/label/comment 按字段落库。
8. 失败重试：拔盘/只读目录/磁盘满各一次；任务可重试且不产生幽灵文件。

#### 通过标准

- 全流程可完成；网格/计数/facet/导出范围一致。
- 校样 pick/rating/label/comment 按字段落库（`client_proof_feedback` 的 `*_applied_at` 可解释）。
- 失败可重试；无幽灵文件（DB 有行、磁盘无文件或反之）。

**证据**：逐步记录、DB 对账 TSV、输出目录清单、失败注入日志。

**当前阻塞**：真实 2k/5k 素材需用户提供；可先用 1k 合成做流程演练，但结论只能记“合成通过”。

```bash
  --db "$DB" --session "$SID" --labels labels.csv --strict
```

现有 `--strict` 阈值：误杀率 <1%、reject precision ≥99%、复核率 ≤35%、覆盖率 ≥65%。这与计划里的“triage 与人工一致 ≥80%”是两套口径，报告要同时给。

**B. 人脸/质量（工具缺口）**

- 闭眼：`QualityService` 输出 `closedEyeRisk/closedEyeProbability`；需 300–500 张标注（睁/闭、虚焦、正常）算 recall/precision。
- 合焦：人脸合焦 top-1 ≥80%；需人脸框 + 清晰/虚焦标签。
- 审美：`aestheticScore` 已有；1k 张排序算 Spearman ≥0.5。
- 语义检索：top-10 ≥0.8；需查询集 + 相关性标注。
- 时延：`quality.score` p95 <1.5s/张（release，排除首次模型加载）。
- 现有 `gather-face-benchmarks` 只覆盖 embedding/聚类，**不覆盖闭眼/合焦/审美准确率**；D6 前需补一个只读评估 CLI 或脚本，否则这些指标记“未验证”。

#### 通过标准

- 闭眼 recall ≥0.85、precision ≥0.90、误杀 <5%。
- 人脸合焦 top-1 ≥80%；审美 Spearman ≥0.5；语义 top-10 ≥0.8；p95 <1.5s/张。
- triage 与人工一致 ≥80%，且 `gather-triage-eval --strict` 通过。

**决策**：全达标 = 可用“自动初审”文案；任一未达标 = 只保留“建议/复核”，文案在发布说明中降级。

**证据**：混淆矩阵、阈值、失败样本目录、时延分布（JSON/CSV）。

**当前阻塞**：标注集与授权。

## 附录 A：V1 夹具规格

- 基底：真实相机 JPEG 或 `sips`/Pillow 生成的 1600×1000 JPEG；颜色 profile 用系统 sRGB。
- 段顺序：SOI → APP0(JFIF) → APP1(Exif) → APP1(XMP) → APP13(Photoshop 3.0 + 0x0404 IIM) → APP2(ICC) → DQT/SOF/DHT/SOS。
- XMP：`dc:title/description/subject/creator`、`photoshop:Headline/City/Country/Credit/Source/DateCreated`、`xmpRights:Marked/WebStatement/UsageTerms`、`lr:hierarchicalSubject`。
- IIM：1:90 UTF-8；2:05 ObjectName；2:25 Keywords×3；2:55/2:60 日期时间；2:80 By-line；2:110 Credit；2:115 Source；2:116 Copyright；2:120 Caption；2:90 City；2:101 Country。
- 大 IPTC：IIM 总量 60KB 的单 APP13 作“正常大样本”；>64KB 拆两个 0x0404 作“负向样本”，标注非标准。ImageIO 实测只读其中一段（见 `v1-imageio-probe.log`），因此不要求全量往返。
- 每个夹具附 `.sha256` 与生成参数（seed/尺寸/字段值）。
