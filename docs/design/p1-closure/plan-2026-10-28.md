### 复核中新发现的 3 条

1. **移出只处理被选中的代表行**：`CullingService` 的 pickState 更新会写同资产所有变体（`CullingService+Commands.swift:81-84`），而移出按 `photoIds` 逐条搬（`LiveCullingAPI.swift:145-155`）。结果：RAW+JPEG 同时淘汰，只搬走 JPEG，RAW 仍是「已淘汰」且占着网格。→ A1 一并修（服务端按资产展开）。
2. **模板/triage 读盘值只读侧车**：`LiveMetadataAPI.swift:238`、`TriageWritebackService.swift:69` 都直接调 `xmp.readAttributes`。JPEG 内嵌 IPTC/rating 的「盘上值」因此读不到，preview 的冲突判定与 triage undo 的「当前星级」都基于不完整快照。→ B1 提供 `MetadataService.diskAttributes` 统一入口。
3. **schema 版本有第二个镜像**：`Schema.swift:13` `currentSchemaVersion = 4` 是 `check-docs.sh` 的唯一代码源（`check-docs.sh:24`），且没有测试断言它等于 `SchemaCurrent.userVersion`。→ C2 补镜像同步 + 断言，避免 V5 时文档门禁判绿而库是 V4。

## 2. 设计

### 2.1 Schema v5：`photos.archived_at` 与统一可见性

```sql
ALTER-equivalent（单版本 DDL 直改，无迁移链）：
photos: 末尾追加 archived_at TEXT   -- NULL = 在工作区；非 NULL = 已移出（不删除，可人工找回）
新计数：44 表 / 385 列 / 72 索引 / 65 外键，user_version = 5
```

- 只加列、不加索引：可见性谓词恒为 `archived_at IS NULL`，与 `session_id` 组合走既有 `idx_photos_session`；`_rejects` 通常占会话 <5%，partial index 收益不足，避免索引计数/fingerprint 再漂移。
- 同步点：`SchemaCurrent.userVersion/expectedColumnCount/expectedShapeFingerprint`、`SchemaCurrent+DDLCore.swift` 头部计数、`Schema.swift` 镜像、`gather-schema` 注释、`SchemaCurrentTests` 逐表列数（photos 14→15、总数 385）、`DatabaseFacadeTests` 的 V4 文案/断言、ADR「当前 schema」句。
- 指纹取值流程照旧：先改 DDL 与计数，跑一次正确库让 open 报实际指纹，再粘贴（禁止用 DDL 自动计算，否则旧库能自证当前）。

**可见性单一入口**（新增 `GatherPersistence/Database/Queries/PhotoVisibility.swift`）：
```swift
public enum PhotoVisibility {
    public static func visible(_ alias: String = "p") -> String { "\(alias).archived_at IS NULL" }
}
```

### 2.2 淘汰移出：语义与文件系统原子性

1. **展开资产**：请求 id → 该 `asset_id` 的全部变体（`asset_id` 为空则只有自己）→ 并集。
2. **过滤而非整批拒绝**：逐张判定 `session 归属 / decision == reject / archived_at IS NULL`；不合格进 `skipped[{photoId, reason}]`，合格才搬。这解决「选中集混进一张保留件，一张都移不动」。
3. **共享边车**：按 `TSPath.xmpSidecarPath` 归一化分组；组内仍有兄弟留在工作区 → **复制** `.xmp`（及 `<xmp>.gather-backup-*`，改新名前缀）；全部移出 → **移动**一次。`movedFiles` 记录 `copy/move` 两种回滚动作（复制→删目标，移动→搬回）。
4. **DB 同一事务**：`photos.filepath` + `archived_at` + 既有 `relocateMetadataState`/`relocateSidecarBinding`/`asset_files`。共享边车时**不迁移** binding/deliveries/keyword_origins（原路径仍属留下的兄弟），改为「为新 `_rejects/x.xmp` 建 binding，复制 `sidecar_metadata_state`，把被移文件的 `asset_file_id` 从旧 binding 解绑并挂到新 binding」；全部移出时走既有 `relocateSidecarBinding`。
5. **返回**：`moved/newPaths/skipped/failed`；UI 汇总「移出 N 张，跳过 M 张（原因）」，并把 moved 从选择集移除。

### 2.3 跨页选择

- 新增只读接口 `CullingAPI.selectionIds(_ query: CullingSelectionQuery) -> CullingSelectionIds { ids, truncated }`：复用 `pageSorted` 的 base WHERE + `preferredRowPredicate()`，`LIMIT 50_000`，返回当前 scope/filter 下的代表行 id。
- VM：`selectedPhotoIds` 变成跨页集合；reset 刷新不再与首页 id 求交，只在 scope/filter/相似度组切换时清空（现有 4 处 `removeAll` 已覆盖）。
- 「全选」= `selectionIds`（失败/截断时退化为已加载页并提示）；`commit` 的批量决策仍与已加载页求交（宁可漏杀），`moveRejectedOut` 用完整选择集（服务端兜底）。

### 2.4 triage 安全

- `MetadataApplySnapshot` 增 `appliedRating: Int?`；apply 时写入本批目标星级。
- undo：先并发（8 路）读盘上 rating，仅当 `当前 == appliedRating` 才回写 `beforeRating`；否则跳过并进 `failed/skipped`（「盘上星级已被改动，跳过」）。旧批次无 `appliedRating` 时按「不回写」处理（fail-closed，不做无条件覆盖）。
- `MetadataAttributesApplyOutcome` 增 `uncertain: [String]`：入队 + flush 成功、但回读失败/校验不符 → uncertain。批次裁剪统一为 `written ∪ uncertain`（模板与 triage 同口径）；`written ∪ uncertain` 为空才 `markUndone`。
- 3/1 策略：新增 `TriageRatingMode { keep3Reject1(默认), keep3Only, none }`，随 `TriageWritebackInput.ratingMode` 传入（缺省保持现状，不偷偷改默认），triage 面板加「淘汰件写 1★」下拉；planner 按 mode 产出 rating。

### 2.5 keepExternal 与投影合并

- planner：`externallyModified = disk != nil && diskValue != currentValue`（删掉 `currentValue != nil`）。语义：缓存没有该字段而盘上有 → 未知即冲突，keepExternal 不覆盖；overwrite 仍写。
- `MetadataCacheRepo.updateDescriptive`：读旧 `iptc_json` → 解码 → 按字段 `applying(incoming)`（`replaceContact == true` 时整块替换 contact）→ 写回；读-改-写在 `connection.transaction` 内。缺行仍 INSERT。
- Converge 传 `replace_contact`（写回 payload 里有就尊重），其余不变。

### 2.6 B1：JPEG 内嵌 IPTC 读取

新增纯映射（`MetadataService` 内，可单测）：`descriptiveFromParse(_ segments:)`，来源优先级 `dc > xmp > iptc`：

| 字段 | dc/xmp 键 | IPTC-IIM 键（ImageIO 实测） |
|---|---|---|
| title | dc:title | `ObjectName` |
| caption | dc:description | `Caption/Abstract` |
| creator | dc:creator | `Byline` |
| copyrightNotice | dc:rights | `CopyrightNotice` |
| headline/credit/source | photoshop:Headline/Credit/Source | `Headline`/`Credit`/`Source` |
| city/state/country | photoshop:City/State/Country | `City`/`Province/State`/`Country/PrimaryLocationName` |
| countryCode | Iptc4xmpCore:CountryCode | `Country/PrimaryLocationCode` |
| sublocation | Iptc4xmpExt:Sublocation | `SubLocation` |
| captionWriter | photoshop:CaptionWriter | `Writer/Editor` |
| creatorJobTitle | photoshop:AuthorsPosition | `BylineTitle` |
| dateCreated | photoshop:DateCreated | `DateCreated` |
| usageTerms | xmpRights:UsageTerms | `UsageTerms` |
| scene | Iptc4xmpCore:Scene | `Scene` |

- 值解包：ImageIO 的 rdf:Alt 值是「带 qualifier 的 tag 数组」，统一 `textValue`（string / 数组首元素 / number→string），空串归一为 nil。
- 删除 `keywords == nil && iptc["Keywords"] != nil → return nil` 的死分支（ImageIO 会把 IIM 合成为 `dc:subject`，实测；保留只会把可读文件推给不存在的 embeddedReader）。
- `mergeAttributes` 的描述性元数据改为**逐字段** `base.applying(overlay)`（侧车覆盖内嵌，内嵌补空），不再整块丢弃。
- 新公开入口 `MetadataService.diskAttributes(photoPath:)`：JPEG 走 exif 解析 + 内嵌映射 + 侧车覆盖；RAW 只读侧车。模板 preview/apply、triage apply/undo 全部改用它（同时修好「盘上 rating」）。
- 缓存投影不变：scan 已把 `writerAttributes.descriptive` 写入 `iptc_json`，B1 后内嵌值自动进入筛选/facet。

### 2.7 B2：单张编辑器

- `MetadataTemplateService` 抽出 `applyFields(fields:photoIds:policy:now:batchId:templateId:templateName:)`；`apply(templateId:)` 只负责查模板后转调。
- `MetadataAPI.applyDescriptive(_ input: Confirmed<MetadataInlineApplyInput>)`：`photoIds + fields`，内部 `applyFields(..., policy: .overwrite, templateId: "inline", name: "手动编辑")`，返回同一个 `MetadataApplyResult`（batchId 可用于既有 `undoTemplate`，`MetadataTemplateService.undo` 的类型守卫放行 inline）。
- 输入上限 2000 张（与模板一致）；字段三态沿用 `DescriptiveMetadata`（nil 不触碰 / 空清空）。
- UI：`MetadataEditorSheet`（32 字段 + contact 8 成员；以缓存值为初值，只提交「用户改过的字段」，contact 逐成员 diff）；入口在 Culling/Gallery inspector 的「编辑元数据…」；应用后提示「JPEG 写入仍为侧车，Bridge 可能读内嵌」。
- 内嵌写入（真正改 JPEG）不在本轮，作为 B2 之后的 spike。

### 2.8 C1：摄取 EXIF

- `IngestService` 注入 `exif: (any ExifProvider)?`；`plan` 改 `async throws`（30+ 测试调用点补 `await`）。
- 每文件捕获 `(DateTimeOriginal → DateTimeDigitized → mtime → now, ifd0.Model ?? exif.Model)`，解析并发 8 路；解析失败只降级到 mtime，不让整批失败。
- 模板展开用捕获日期（本地时区解析 `yyyy:MM:dd HH:mm:ss`）；`{camera}` 用 Model（沿用 `sanitize`）。
- `LiveSessionAPI` 注入 `ImageIOExifProvider()`；补 JPEG/RAW 用例：EXIF 日期进目录、无 EXIF 用 mtime、`{camera}` 非空。

### 2.9 C2 + P2

- **watcher 窄扫描**：`metadataScan(requestedPaths: change.directories)`；`jobs.start` 后用 `jobs.list` 比对返回 job 的 checkpoint：若是全树（无 requestedPaths）或覆盖本次目录 → 成功；若是更窄的活跃任务 → 保留 pending 目录、2s/4s/8s/16s 退避重试，最多 4 次，仍不行则退回一次全树扫描（保底覆盖），全程 eventID 只在覆盖成功后持久化。

- **preview 并发**：`previewTemplate` 的逐张读盘改 `batchAsync(concurrency: 8)`。
- **门禁**：`Schema.swift` 镜像 + 新断言 `currentSchemaVersion == SchemaCurrent.userVersion`；`check-docs --strict`、12 个 check-*.sh（strict）、l10n parity、schema verify。

## 5. 未决问题（推荐选项）

1. **triage 3/1 是否保留**：推荐「默认不变 + UI 可切 keep3Only/none」，产品拍板前不偷偷改默认（A2.3 已按此实现）。
2. **移出是否可撤**：推荐保持单向（`_rejects` 人工找回），不提供 undo；文档写明。若后续要 undo，需存原路径与新 `archived_at` 的逆操作。
3. **模板上限 2000 是否够**：推荐 2000（settings 快照 ~2MB 上限）；若确有 5000 张场景，改为「超过 2000 只记 id 不记 before」会破坏 undo，故不推荐。
4. **`sessions.photo_count` 是否减 archived**：推荐不减（物理登记数），只在 UI 文案区分「工作区 N / 已移出 M」；改了会影响工作区状态与既有测试。

## 6. 风险

- **schema 一次性 reset**：V5 会让本地 V4 库改名 `.incompatible-*`，测试/开发库需重建；这是既定策略（无迁移链）。
- **共享边车复制**：两处 `.xmp` 之后可能各自演化，属预期（移出件已离开工作区）；不复制 deliveries，避免把未完成的写回带到 `_rejects`。
- **窄扫描与手动扫描并发**：靠 dedupeKey 的 checkpoint 检查 + 退避 + 全树保底；最坏退化为现状。
- **B2 UI 体积**：32 字段 + contact 表单是本轮最大 UI 面，先用单列 ScrollView，不做分组折叠。
