# Swift 人脸识别架构替换与素材验证（2026-10-03）

已将生产默认编码器从 Vision 通用图像特征切换为离线 SFace CoreML 身份模型，并把人工身份/纠错与可重建的观测、聚类、人物向量分离。实施前的工作区已提交为 `ad9df1b`。本轮只构建和验证 Swift 版本。

## 模型与运行路径

`RAWDecoder → Vision 人脸/关键点/采集质量 → 五点 sRGB 112×112 对齐 → SFace CoreML FP32 → 128 维单位向量 → 质量约束聚类 → 人物级竞争匹配 → 人工确认 → 关键词写回`。

默认模型随 SwiftPM 资源和原生应用分发，正常使用无须 Python、ONNX Runtime、联网下载。保留显式的 VisionFeaturePrint 对照评测实现，生产不会自动回退到它。自定义 CoreML 模型仍可使用，输入须为单一 112×112 图像，输出须能明确选取身份向量；加载错误直接报错。

采用 SFace 的依据是可分发许可、原生运行和实测表现。OpenCV Zoo 的 SFace 目录明确以 Apache-2.0 提供全部文件；InsightFace 代码许可与预训练权重许可不同，不能仅因代码 MIT 就把 buffalo_l 权重作为产品默认资产。这是目前有证据支持的部署方案，尚未证明是所有摄影场景中准确率最高的模型。

- [OpenCV Zoo SFace 固定版本](https://github.com/opencv/opencv_zoo/tree/47534e27c9851bb1128ccc0102f1145e27f23f98/models/face_recognition_sface)
- [SFace 文件许可](https://github.com/opencv/opencv_zoo/blob/47534e27c9851bb1128ccc0102f1145e27f23f98/models/face_recognition_sface/LICENSE)
- [InsightFace 代码与模型许可说明](https://github.com/deepinsight/insightface/blob/master/python-package/README.md)

模型转换脚本固定上游提交和 SHA-256，依赖版本单独锁定。ONNX → CoreML 转换经过零值、随机和渐变输入核对，余弦一致性至少 0.99999994、最大绝对误差不超过 1.76e-6；另有独立 ONNX 参考向量验证 Swift 的 Vision/CoreML 图像封装，防止颜色通道或预处理差异。资源包含原始许可、来源、精度与转换记录。

## 持久化与决策

- 数据库升级至 v35，新增 `face_identity_feedback`，通过会话、照片和人脸框记录确认/拒绝，而不依赖重分析后会变化的观测编号。几何匹配采用 IoU ≥ 0.5。
- 模型迁移先在数据库外准备全部新观测；检测或编码失败、取消、原始文件变化、会话索引变化、聚类失败时，保留旧观测、身份、聚类与向量。成功时在一个事务内切换。普通同模型增量分析仍保留逐照片缓存提交语义。
- 观测删除/替换前解除成员外键，保留成员几何供身份恢复。失效人物向量同步删除，随后按当前人工绑定重新建立。
- 人物库匹配必须来自可追溯观测，且权重、预处理和版本规格相同。没有来源的旧向量不参与自动身份匹配；相同维度不能作为兼容依据。
- 人工确认优先于距离聚类；拒绝记录独立保留并进入可审核结果。重新分析/重聚类不会自动恢复被拒绝的身份。显式重新绑定可以覆盖同一身份的拒绝，合并会写入目标人工身份。
- 自动身份建议取整个簇对各人物的匹配分数中位数，再比较人物级冠军与亚军。亚军即使未达到自己的接受阈值也会产生歧义；近似并列不自动猜测。增量质心归属采用同样的竞争原则。
- 人物投影按稳定身份 ID 重建，同名显示名称不会覆盖两个已明确绑定的人物。
- 绑定、解绑、移除成员、合并和人物投影按事务提交；分析与重聚类共用会话占用，防止同时改写。
- 模型缓存只编译同一规格一次；每次推理创建独立请求。设置页显示真实模型存在性，提供自动/CPU 和恢复内置模型，不再要求安装未使用的 ONNX 模型。移除不生效的 ONNX 线程/NMS 控件，改为实际照片解码并发设置；缺失提示、中英文文案与目录模型选择同步更新。
- 质量评估修复归一化坐标被当作像素坐标的问题；评分版本升至 2，并将人脸几何和分析规格纳入缓存输入，避免评分先于人脸分析时永久沿用无主体评分。

## 用户素材对照

只读扫描用户提供的 Selects 目录，处理 141 张 NEF。Capture One 辅助文件未当作照片输入，原文件及元数据没有写回。所有人脸裁剪、向量和原始评测 JSON 仅存放在 `/tmp/gather-face-benchmark-20261003`，未加入仓库。

硬件 Apple M5 Pro，Swift Debug 构建；两次运行使用相同 Vision 检测、五点对齐和质量流程，2048px 预览。编码流程计时含检测、对齐、质量与模型推理，排除模型加载和 RAW 解码；逐图先运行旧方案再运行 SFace，因此属于单机顺序对照，不能当作通用性能保证。

| 指标 | 旧 FeaturePrint | SFace |
| --- | ---: | ---: |
| 成功处理照片 | 141 | 141 |
| 编码人脸 / 成功五点对齐 | 137 / 137 | 137 / 137 |
| 编码失败 | 0 | 0 |
| 输出维度 | 768 | 128 |
| 编码流程总耗时 | 5.527 秒 | 3.472 秒 |
| 每图中位数 | 39.97 毫秒 | 24.25 毫秒 |
| 每图 P95 | 48.03 毫秒 | 33.12 毫秒 |

RAW 解码总计 15.051 秒。SFace 编码流程总耗时下降约 37%，同精度的单条向量容量减少约 83%。

聚类采用 minPts=2、核心质量门槛 0.35；下表展示大小与噪声，不代表身份准确率。

| 余弦相似度下限 | 旧方案簇大小 | SFace 簇大小 | SFace 噪声 |
| --- | --- | --- | ---: |
| 0.50 | 137 | 133、4 | 0 |
| 0.60 | 137 | 133、4 | 0 |
| 0.65 | 137 | 105、28、4 | 0 |
| 0.70 | 137 | 104、28、4 | 1 |
| 0.75 | 133、4 | 81、22、28、4 | 2 |

已目视检查裁剪拼图，素材包含戏曲浓妆、侧脸、表情变化及多人照片。SFace 在这批素材上呈现更好的分组区分能力，但浓妆人脸仍可能桥接、同一人物仍可能被拆分。没有人工逐脸身份真值，不能给出准确率、误识率，也不能认定所有分组都正确。

新安装默认相似度下限和“均衡”预设调整为 0.65；既有用户自定义值不自动改写。0.65 是当前保守起点，不能推广为所有模型/场次的最佳阈值。跨场次、低光、遮挡、不同化妆状态仍需带真值的独立样本评测。

复现工具：

```bash
swift run --package-path desktop/native/gather-core gather-face-benchmarks <只读素材目录> <素材目录之外的输出目录>
```

输出含逐照片耗时、模型规格、框、质量、向量及六档阈值聚类结果。评测报告属于私人素材派生数据，默认仅写到调用者明确指定的本地目录。

## 验证与边界

- 核心测试 994 个、界面测试 298 个通过；含真实 CoreML 推理、独立 ONNX 参考核对、相同维度不同模型隔离、失败/取消迁移回滚、成功迁移身份保留、拒绝记录重聚类保留、同名身份分离、归一化质量区域和质量缓存失效。
- 原生 Debug 和 Release 应用成功组装；指定打包后的资源目录完成独立人脸推理，确认包内模型可加载。修复 SwiftPM 资源采用 `Contents/Resources` 布局时的模型校验及本地化复制。
- 本轮未启动用户正式安装的应用，也未迁移用户正式数据库；现有测试数据库的迁移和回滚已验证。未进行 Electron 测试。
- 完整 UI 实机操作、正式签名/公证、Intel Mac、真实大图库峰值内存和不同 CoreML 硬件后端尚未验收。当前产物未签名。
- 大规模跨人物库仍使用精确人物样本比较；现有大规模聚类有 LSH 候选与精确复核，但这次没有完成带标签的大库检索召回率评测，不能宣称 ANN/自动命名已达到竞品最佳水平。
