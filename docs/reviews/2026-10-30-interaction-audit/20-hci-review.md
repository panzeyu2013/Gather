# 从人机交互与既有软件习惯，再审上一版整改计划

> 前置：`00-macro-overview.md`、`10-synthesis.md`（缺陷清单与优先级）。
> 本文不复述缺陷，只回答三个问题：
> ① 这些缺陷在"人的操作习惯"里意味着什么；② 上一版计划哪里排错了；③ 应该改成什么。

---

## 0. 一句话结论

上一版计划能修好"东西坏了"，但修不好"人用起来别扭"。
分界线是：**缺陷按清单修，习惯按场景重排**。上一版把两者混在一个 P1 列表里，导致三条高频问题排在三条低频问题之后。

## 1. 参照系：用户是从哪来的

产品定位是 Capture One 的伴侣（`README.md:5`），但摄影师的实际桌面是 C1 + Lightroom Classic + Photo Mechanic + Bridge + 访达 + 照片。肌肉记忆不是从空白建立的，是从这五个软件里迁移来的。

| 行为 | 既有软件的约定 | Gather 现状 | 判定 |
| --- | --- | --- | --- |
| P / X / U 标记 | Lr Classic：P 留、X 弃、U 取消标记 | 相同（查看器 `onKeyPress`） | ✅ **继承正确**，这是最关键的三个键 |
| 1–5 星级 | Lr / PM / C1 一致 | 相同 | ✅ |
| 6–9 色标 | Lr：6–9 直接给红/黄/绿/蓝标 | 无快捷键，颜色只在检查器菜单里 | ⚠️ **缺失**（见 §2.5） |
| Space | Lr：放大切换；PM：预览 | 挑片 = **保留**；浏览 = **切换选择** | ❌ **双义冲突**（见 §2.1） |
| ← / → | 所有：上一张 / 下一张 | 挑片 = 上一张/下一张 ✅；浏览 = 移游标不换照片 | ⚠️ 一页对一页错 |
| Return | 访达 / Lr：打开 | 浏览 = 开灯箱 ✅；工作台 = **无反应** | ❌ |
| 双击 | 所有：打开 | 工作台行、挑片网格单元 = **无反应** | ❌ |
| ⌘A | 所有：全选 | 浏览有（且是 20k 服务端全范围）；挑片**只在网格布局**有 | ⚠️ |
| ⌘⌥S 侧栏 | 访达 | 相同 | ✅ |
| ⌘R 刷新 | 普遍：重读、**不丢上下文** | 图库：清空选择 + 回顶 | ❌（见 §2.4） |
| ⌘Z | 所有：撤销 | 挑片有自建栈；其他页面只有系统文本撤销 | ⚠️ 半套 |
| ⌘W / ⌘N | 关窗 / 新建 | ⌘W 后 File 菜单全灰、无 ⌘N | ❌ |

**这张表最重要的一行是 P/X/U**：作者把这一行继承对了，说明设计时有意识地对齐了专业工作流。问题出在"移动、打开、选择"这三类**更基础**的键位上——它们没有统一建模，而是每页各自实现。

## 2. 五处会让人"按错"的地方

### 2.1 Space 双义（最危险）

- 挑片：`CullingWorkbenchViewer.swift:174-176` → `case " "` 提交 `pickState: .picked`（= 保留）。
- 浏览：`GalleryGrid.swift:57` → `toggleGalleryCursor()`（= 切换选择）。

同一个键，在同一个会话的两个页签里做两件事，且**都会改变持久状态**。Space 是"盲操作键"——用户眼睛在照片上，不看键盘。按错的代价不是"没反应"，是"悄悄给一张片打了保留"。

更麻烦的是它同时和 Lr 的 Space=放大冲突。三个语义挤在一个键上。

### 2.2 方向键：一页对、一页错

挑片里 ←/→ 是"上一张/下一张"（`Viewer:157-166`），符合所有照片软件；浏览里 ←/→ 只是移动一个**看不见的**游标（`GalleryView+Content.swift:325-337`），照片不换、灯箱不开、游标无视觉。用户会以为"方向键坏了"。

这不是"惯例冲突"，这是**惯例只落实了一半**。

### 2.3 Return / 双击：macOS 最基本的"打开"

- 工作台会话行：只有行尾「进入」按钮和右键菜单（`SessionRowView.swift:35,142`），双击与 Return 无反应。
- 挑片网格单元：只有 `onTapGesture`（`CullingGrid.swift:265-288`），双击不打开单图。

在访达里双击打开是 1984 年就定下的契约。一个原生 macOS 应用里"点了没反应"，用户的第一反应不是"这功能没做"，而是"这软件卡了"。

### 2.4 刷新 = 清空上下文

浏览器、访达、Lr 的"刷新/重读"都保上下文。Gather 的 ⌘R 会清选择 + 回顶 + 整页转圈（`GalleryViewModel+Load.swift:28,93`）。

HCI 上这是"控制感"问题：用户按刷新是想"看看有没有新东西"，不是想"丢掉我正在做的事"。

### 2.5 色标没有快捷键（缺失而非冲突）

Lr 用户的手指记得 6/7/8/9。Gather 里按 7 什么都不会发生（`Viewer:191-194` 只处理 0–5 作为星级）。缺失比冲突温和，但它是"专业感"的一部分——色彩标记在挑片里的使用频率仅次于星级。

## 3. 用 HCI 原则复检（只写有新结论的）

| 原则 | Gather 现状 | 结论 |
| --- | --- | --- |
| **反馈时延 <100ms（Nielsen）** | `commit` 没有 in-flight 状态、没有乐观 UI，必须等 API 回来才前进（`CullingViewModel+Actions.swift:211-254`） | 核心循环的每一拍都在等网络/落库。**且没有串行化**：连按 P 会针对同一 `expectedRevision` 发两次请求，第二次大概率以 revision 冲突收场，弹一条错误横幅。挑片是 2–3 次按键/秒的工作流——这是**结构性问题**，不是 bug |
| **错误预防 vs 事后纠正** | 重复页对"可逆"的保留/丢弃逐张弹确认；挑片对"不可逆"的移到 `_rejects` 却不报张数 | **保护倒挂**：可逆的拦得死，不可逆的放得松 |
| **撤销优于确认（Nielsen/Gmail 范式）** | 全应用只有挑片有撤销栈 | 重复/人物/元数据的确认框，本该用"撤销"替掉 |
| **Fitts 定律** | 页签 24pt 高、工具栏图标 22pt 命中区、检查器决策按钮 minHeight 24 | 低于 macOS 常规 28pt；挑片是长时间高频点击，误点成本高 |
| **Hick 定律** | 挑片首屏：动作条 7 控件 + 筛选条 6 控件 + 检查器 14 段 | 选择成本高；建议"模式 / 过滤 / 属性"三级下沉 |
| **识别优于回忆** | P/X/U 角标印在按钮上（好设计） | 但焦点不在查看器时角标是**假的**——识别辅助变成欺骗 |
| **用户控制与自由** | 无统一的"取消正在进行的分析"位置；⌘W 后无 ⌘N；控制中心任务不能取消 | |
| **一致性与标准** | 错误样式两套皮、术语 工作区/会话 分叉、日期不跟 locale | |

## 4. 对上一版计划的逐条反思

图例：**保留**＝照做；**修正**＝方向对但做法要改；**降级**＝不是这个优先级；**新增**＝漏了。

| 上一版 | 反思 | 修正后动作 |
| --- | --- | --- |
| P0-1 toast 命中测试 | **保留，但定性要改**：修好它只是"让按钮能点"，不等于"错误有了出口"。导入失败应该落在**目标上下文**（图库顶部常驻条），而不是 5 秒后消失的浮层 | 修 hit-testing（10 分钟）；同时把"需要用户动作的错误"从 toast 迁到页内常驻 banner |
| P0-2 多 dialog 同节点 | **保留**。这是我全会话里唯一"不修就没法用"的候选 | 先验后修；照重复页拆节点 |
| P1-1 缩略图缓存失效 | **修正为更大的一件**：只加 mtime 进 key，会把"永不更新"换成"每次都 stat + 可能闪烁"。真正要对齐的是 C1/Lr 的**外部变更感知**（FSEvents → 只失效变动文件 → 局部重绘） | 分两步：①mtime 进键（止血）②FSEvents 驱动失效 + 网格内"已更新"微提示 |
| P1-2 相似度回页清空 | **修正做法**：清空很可能是在防"看到过期结果"。正解不是"保留原样"，而是**保留 + 明确标记过期**（顶部条：结果基于 2 小时前的分析，[重新分析]） | 同理适用于挑片/导出 |
| P1-3 侧栏切会话 → 返回横跳 | **保留**（真 bug，与习惯无关） | 切会话不写 `previousRoute` |
| P1-4 刷新语义统一 | **修正**：一刀切成"就地刷新"会让用户失去恢复手段。需要**双档**：⌘R 软刷新（保选择、保滚动、顶部细进度）、⌥⌘R 硬重载（清空重来） | 与浏览器/访达的心智一致：刷新保上下文，"强制重载"是显式的 |
| P1-5 焦点三件套 | **修正**：不要给照片画焦点环——专业工具里查看器从不显示焦点装饰。改用**键盘作用域**：页面级命令常驻（文本框例外），焦点只影响"谁吃字符键" | 页面级 `@FocusState` 兜底 + 文本框 opt-out；不加装饰 |

| P1-7 控制中心整页转圈 | **保留**，但只改一半不够：应"首载转圈、后续静默" | `isLoading && session == nil` 才显示 ProgressView |

## 5. 按"频率 × 伤害 × 可逆性"重排

上一版按"用户可见伤害"排序，漏了频率。挑片一天几百次，设置一个月一次——它们不该在同一条 P1 里。

### L1 · 肌肉记忆层（每天几百次，错了就废）
1. 决策提交串行化（连按 P 不冲突）——**新增，上版没有**
2. 键盘作用域：无初始聚焦 → 页面级命令（不动查看器装饰）
3. Space 双义裁决（§6-A）
4. Return / 双击打开（工作台、挑片网格）
5. 色标 6–9
6. 方向键：浏览页要么换照片、要么明示游标

### L2 · 状态信任层（每周，错了会重做）
7. 刷新双档（软/硬）
8. 完成态保留 + 过期标记（相似度 / 挑片 / 导出）
9. 缩略图新鲜度（mtime + FSEvents）
10. 控制中心静默刷新
11. 人物自动保存

### L3 · 恢复与安全层（低频，错了会丢数据/被吓到）
12. ResetImpactSheet 默认键
13. 错误通道分层（需要动作的 → 常驻页内；瞬时的 → toast）
14. 撤销替代可逆确认
15. 写回命名词与张数
16. 多 dialog 拆节点
17. 设置页加载态

## 6. 需要你拍板的四个取舍（这些不是 bug，是产品立场）

**A. Space 在挑片页的语义**
- 保"保留"：现有用户肌肉记忆不破；Lr 迁移用户会误标。
- 改"放大切换"：对齐 Lr；现有用户会误操作（而且是**静默**的标记动作）。
- 第三条路：**Space = 保留，但仅在"自动前进开启"时**；关闭自动前进时 Space = 放大。用模式消歧，代价是"同一个键两种行为"仍未根除。
- 我的建议：保留"保留"，但把 Lr 的放大语义交给 `Z`（Lr 的 Z 就是 100% 缩放），并在首次进入时给一次可关闭的提示。

**B. 返回箭头的去留**
没有任何同类软件在页签条左侧放返回箭头。它同时承担"离开会话 / 回上一页 / 回工作台"三种语义。
- 建议：改名为「返回工作台」并把目标写进 tooltip；页级返回交给左侧栏（本来就有）。这样语义唯一，也符合"导航走导航栏"的习惯。

**C. 刷新是单档还是双档**
- 单档"就地"：简单，但丢失恢复手段。
- 双档（⌘R 软 / ⌥⌘R 硬）：多一个可学项，但符合浏览器/访达/IDE 的普遍做法。建议双档。

**D. 页签条放哪**
- 留内容列：省工具栏空间，但吃掉 40pt 垂直，且永远是第 4 层 chrome。
- 上移工具栏：垂直还给照片（挑片页尤其需要），但要重做一套 tab UI。
- 建议：**挑片/浏览这类"看图页"上移；控制中心/导出这类"表单页"留内容列**——按页面类型分，而不是统一。

## 7. 方法论反思：上一版为什么漏了这些

1. **只审了"代码做了什么"，没审"人期待什么"**。六个 subagent 都在验证实现与文档是否一致，没有人拿 Finder/Lr 的默认行为当基线。
2. **把"缺陷密度"当成了优先级**。B 组 9 个 P1、C 组 30 条——数量多不等于重要。真正该先修的是"每天出错一次"的那条。
3. **默认"一致性"是好事**。实际上有些"不一致"是对的（挑片和浏览本来就该有不同的键位语义），而有些"统一"会制造新问题（统一刷新会丢恢复手段、统一焦点环会污染媒体呈现）。
4. **没有一个"时间维度"**。专业工具的手感由**节拍**决定：按下 → 看到 → 下一张，必须在一个呼吸内完成。上一版没有任何一条关于"一拍多长"。

## 8. 给下一版的执行建议

- 先做一次 **30 分钟的实机节拍测试**：用 100 张片，只按 P/X，记录"平均每张耗时"和"误操作次数"。这个数字会决定 L1 全部工作的价值。
- L1 改完后复测同一指标，作为唯一验收口径。
- L2/L3 按上述顺序推进，不再按模块切分——因为它们跨模块。
